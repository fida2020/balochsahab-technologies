# Baloch Sahab Technologies website — content & deployment guide

The site is plain static HTML served by GitHub Pages (repo `fida2020/balochsahab-technologies`, branch `main`, custom domain in `CNAME`) behind Cloudflare. There is no database or server. Pages are generated by a small Node script with no dependencies (Node 18+).

## Managing products and client projects

All projects live in `content/projects.json`. Only people with write access to the GitHub repository can change them — that is the authentication/authorization for content changes. Keep the repository's collaborator list minimal and 2FA on.

| Task | What to do |
|---|---|
| Add | Copy an existing entry, change `slug` (lowercase-kebab-case, becomes the URL), fill the fields |
| Edit | Change the fields of the entry |
| Publish / unpublish | Set `"published": true` / `false` (unpublished pages are removed from the site and sitemap) |
| Delete | Remove the entry |
| Feature on homepage | `"featured": true` (products only appear on the homepage when featured) |
| Order | `"order"`: lower numbers first |

Field rules (checked by the build — it refuses invalid content):

- `kind`: `"product"` (company-owned → `/products/<slug>.html`, listed on **Our Products**) or `"client"` (customer work → `/work/<slug>.html`, listed on **Client Work**). The two are never mixed.
- `status`: `live`, `beta`, `in-development`, `completed`, `maintained`.
- `category`, `tagline` (≤160 chars), `summary` (≤300), `overview` (paragraphs), `features`, `technologies`, `platforms`, `notes` (lists of text).
- `images`: `[{ "src": "/assets/img/products/<file>.png", "alt": "...", "caption": "..." }]` — the file must exist. Only add real screenshots you are allowed to publish.
- `links`: `[{ "label": "...", "url": "https://...", "primary": true }]` — https only.
- Client work additionally needs `"client": "Client name"` and **`"clientAuthorized": true`** (only set after written client permission); otherwise the build refuses to publish it.

Only publish verified information.

## Editing other pages

Page text is in `tools/pages.mjs`; the shared header/footer/SEO tags are in `tools/layout.mjs`; site-wide settings (emails, phone, form endpoints, AdSense id) are in `tools/lib.mjs`. **Do not hand-edit the generated `.html` files, `sitemap.xml` or `robots.txt`** — they are overwritten by the build.

## Build and test (always before pushing)

```
node tools/build.mjs        # validate content + regenerate pages, sitemap.xml, robots.txt
node tools/test.mjs         # automated checks (links, assets, SEO tags, sitemap, forms, separation)
python -m http.server 8765  # optional local preview at http://127.0.0.1:8765/
```

GitHub Actions (`.github/workflows/check.yml`) re-runs the build check and tests on every push and pull request.

## Forms

Contact (`/contact.html`) → info@balochsahab.com, Quote (`/quote.html`) → sales@balochsahab.com, delivered through FormSubmit (https://formsubmit.co) AJAX endpoints set in `tools/lib.mjs`. No API key is needed or stored.

**One-time activation:** the first submission to each address makes FormSubmit email an activation link to that address. Click it in each inbox (info@ and sales@). Until then the forms correctly show an error with the email fallback, never a false success. Mail for `@balochsahab.com` is routed by Cloudflare Email Routing — make sure both addresses forward to a monitored inbox.

## Deploy

1. Work on a branch, run build + tests, preview locally.
2. Merge into `main` and push. GitHub Pages publishes in ~1–3 minutes.
3. Check https://balochsahab.com/ and the changed pages; purge the Cloudflare cache if old CSS shows (asset URLs are versioned, so this is rarely needed).

## Backup and rollback

- Recovery point for the pre-redesign site: tag `backup-pre-redesign-2026-10-11` (commit `b8ee75d`), pushed to GitHub.
- Roll back the live site to it (keeps history, no force-push):
  ```
  git checkout main
  git revert --no-edit <first-redesign-commit>^..HEAD   # or: git revert -m 1 <merge-commit>
  git push origin main
  ```
- Emergency full restore of the old files: `git checkout backup-pre-redesign-2026-10-11 -- . && git commit -m "Restore pre-redesign site" && git push`. (New files added by the redesign remain but are unlinked; delete them if needed.)
